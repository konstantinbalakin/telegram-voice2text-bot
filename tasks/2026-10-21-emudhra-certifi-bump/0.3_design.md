# Дизайн: закрытие eMudhra-уязвимости в образе бота

Статус: утверждён К. («я ок», 2026-10-21). Правок по ревью нет.
Решения из 0.2: certifi → 2026.10.19 (В1); apt + вырезание корня при сборке (В2=а); деплой сразу после мержа (В3); без CI-страховки (В4).

## Контекст

Рантайм бота имеет два TLS-пути, оба в прод-образе v0.0.79 доверяют скомпрометированной цепочке eMudhra (emSign ECC Root CA - G3):

1. **certifi** `2026.1.4` из `requirements.txt` — используется библиотеками, которые явно берут `certifi.where()` (проверено 21.10.2026: dv-g3b-хост принимается).
2. **Системный стор контейнера** `/etc/ssl/certs/ca-certificates.crt` (Debian bookworm из базового образа, дата сборки 2026-10-10) — это путь по умолчанию для рантайма: Dockerfile выставляет `REQUESTS_CA_BUNDLE`/`SSL_CERT_FILE`/`PIP_CERT` на него.

Горячий фикс (docker exec pip install certifi==2026.10.19 + restart 21.10.2026) закрывает только certifi и живёт до пересоздания контейнера. Системный стор в работающем контейнере остаётся уязвимым.

## Изменения

### 1. `requirements.txt`

`certifi==2026.1.4` → `certifi==2026.10.19`.

### 2. `Dockerfile` (блок apt-get)

Добавить `ca-certificates` в существующий `apt-get install` (подтянет свежий пакет из bookworm-security на момент сборки — базовая защита от будущих инцидентов такого рода).

### 3. `Dockerfile` (новый шаг после apt, до COPY requirements)

Вырезать корень `emSign ECC Root CA - G3` из `/etc/ssl/certs/ca-certificates.crt`, если он присутствует:

```dockerfile
# eMudhra CA compromise (Oct 2026): drop the compromised emSign ECC Root CA - G3
# from the container trust store. No-op once Debian ships the fixed ca-certificates.
RUN python3 - <<'EOF'
import re
p = "/etc/ssl/certs/ca-certificates.crt"
data = open(p).read()
blocks = data.split("-----BEGIN CERTIFICATE-----")
kept = [blocks[0]] + [b for b in blocks[1:]
                      if "emSign ECC Root CA - G3" not in _subject(b)]
open(p, "w").write("-----BEGIN CERTIFICATE-----".join(kept))
EOF
```

(итоговая реализация `_subject()` — декодирование subject из PEM; исполнитель оформляет как простой скрипт в `scripts/` или инлайн, по месту.)

Шаг детерминирован: если пакет Debian уже без корня — вырезание не находит блоков и ничего не меняет. Хешированные симлинки `/etc/ssl/certs/*.0` не трогаем: рантайм-пути бота (`REQUESTS_CA_BUNDLE`, `SSL_CERT_FILE`) читают только bundle-файл.

Слой делаем до `COPY requirements*`, чтобы не инвалиджировать слой pip при правке скрипта.
