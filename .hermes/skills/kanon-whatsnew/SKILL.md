# kanon-whatsnew — релизные заметки (R10)

Цель: запись в `WHATSNEW.md` (или `CHANGELOG.md`, если он ведёт релизы)
из артефактов фичи — НЕ из памяти сессии.

## Источники (только они)

- `feature.md` — «Что будет» → что сообщили пользователю
- `iterations/` — найденные при полигоне баги → честные «починили»
- закрытые чекбоксы `plan.md` — факты, НО пользовательский язык
  (не «refactored db.py», а «бот стал отвечать быстрее»)

## Формат записи

```markdown
## [<версия/дата>] — <название фичи>

**Мазки** (3-5 пунктов, ≤ 10 слов каждый):
- <пользовательская выгода>

**Детали:**
- <как работает, когда применимо>

**Скрины/гифки:** <ссылки; alt-текст обязателен — дешёвая vision-модель
поможет сгенерировать>
```

## Запреты (нейрослоп)

- «Мы рады сообщить», «значительное улучшение», «исправлено множество
  ошибок», «стало лучше» без конкретики
- Прилагательные без измеримого смысла (быстрее — на сколько/в чём)
- Пустые категории (Fixed:, в котором ничего пользовательского)
- Длина мазка > 10 слов

## Чек перед публикацией

- [ ] каждая строка проверяема фактом из артефактов фичи
- [ ] пользователь, не видевший код, понимает, что ему стало лучше
- [ ] потребители прогнаны `kanon check` — ноль stale; дрейф у потребителя
      без обновления = релиз не закрыт
- [ ] запись в том же коммите, что и `status: released`
