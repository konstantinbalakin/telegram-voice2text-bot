# kanon-docsync — синк техдоки (R9)

Цель: `docs/dev/` отражает код ПОСЛЕ изменений фичи. Синк — условие
готовности (DoD), без него фича не released.

## Порядок

1. Прочитай `docs/dev/index.md` — что задекларировано.
2. Пройдись по touched-областям фичи и сверь с кодом:
   - изменил архитектуру → `architecture/`
   - изменил интерфейсы (HTTP/CLI/API библиотеки) → `api/`
   - изменил данные/схемы/форматы → `data/`
   - новый файл-контракт → новый атомарный док, ссылка из index
3. Формат правок — дельта (по OpenSpec): не переписывать док целиком,
   а точно отметить ADDED / MODIFIED / REMOVED относительно фактов.
4. Дубли запрещены: факт живёт в одном доке, остальные — ссылки
   (SSoT). Появился дубль — убей младший, оставь ссылку.
5. Проверь рендер: если в доке Mermaid — диаграмма обязана рендериться
   (машинная проверка до коммита, mmdc/kroki при наличии).

## DoD-чек

- [ ] корневой `README.md` синкаронен (статус, quick start, структура) —
      он пользовательская поверхность, а не только docs/dev
- [ ] docs/dev/index.md не обещает того, чего нет
- [ ] каждый док ≤ 300 строк (иначе — разбить/прогрессивная загрузка)
- [ ] нет двух доков об одном факте
- [ ] изменения доков в том же коммите, что и релиз фичи
