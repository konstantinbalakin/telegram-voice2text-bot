# kanon-plan — планирование (R5)

Цель: `plan.md` с чекбоксами для фичи в `approved`.

## Адаптивная детализация

| Размер | Признак | План |
|---|---|---|
| тривиальный | 1 файл, механическая правка | 2-4 чекбокса, без секций |
| сессионный | 1 сфера, ясная механика | 5-10 чекбоксов, одной волной |
| эпик | >1 сфера / неясна механика | волны по 3-7 задач + спайк-задача первой |

Режим токен-экономики (из `kanon/config.toml` → `[core] options`,
или спроси оператора): подписка = краткие планы умной модели;
API = детальные шаги для дешёвых исполнителей.

## Формат plan.md

```markdown
# План: <title>

## Волна 1: <имя>          # секции-волны только у эпиков
- [ ] задача 1 — глагол + что + где
- [ ] задача 2
```

Перед задачами — обязательные секции проектирования:

**Пользовательские поверхности**: для каждого состояния, которое создаёт
фича, — где юзер его видит (экран/команда/сообщение). Состояние без
поверхности = юзер «потерял деньги» на его взгляд (пилот #140: /balance
не показывал оплаченную очередь — it-002).

**Матрица составных состояний**: пересечение живых состояний × действий
(напр.: нет подписки / active / active+queued × покупка/истечение).
Каждая непустая ячейка имеет исход до начала кода; ячейки «невозможно» —
помечены с причиной.

Правила задач:
- один чекбокс = один коммит;
- задача начинается с глагола, называет файл/место;
- задача выполнима за одну сессию исполнителя;
- проверки (`kanon check`, тесты) — отдельными чекбоксами, не примечанием.

## После написания плана

1. `status: planned` в frontmatter + запись в `status-log.json` + коммит.
2. Первая задача — та, что даст быстрый видимый прогресс (или спайк,
   если механика неясна).
