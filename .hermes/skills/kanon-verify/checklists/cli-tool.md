# Полигонный чек-лист: cli-tool

Пресет cli-tool (CLI-утилиты без рантайм-сервиса). Прогонять на
полигоне (temp-каталоги с git-репо), не на живых проектах оператора.
Каждый пункт: pass / fail + сырой лог.

## 1. Установка и первый запуск

- [ ] запуск без аргументов → помощь/ошибка с указанием команд, не traceback
- [ ] `--help` у каждой подкоманды → читаемо, без traceback

## 2. Основной сценарий (ядро фичи)

- [ ] основной сценарий утилиты на чистом полигоне → ожидаемый артефакт
- [ ] невалидный аргумент (неизвестный пресет/путь) → понятная ошибка, код ≠ 0
- [ ] основной сценарий на «грязном» полигоне (существующие файлы) →
      чужой контент сохранён, поведение задокументировано

## 3. Границы

- [ ] повторный запуск основного сценария → идемпотентен (diff пустой или planned)
- [ ] повреждённые маркеры/файлы → refuse с сообщением, файлы не меняются
- [ ] неинтерактивный режим (нет TTY) → предсказуемый отказ или явный флаг, не висит

## 4. Инфраструктура

- [ ] запуск из другого cwd (пути не относительные) → корректный результат
- [ ] файлы, которые утилита пишет, — в git-видимых путях, нет скрытого стейта

## 5. Регрессия фичи

- [ ] сценарии из whatsnew прошлых релизов → не сломаны
- [ ] `kanon check` зелёный
- [ ] потребители: `kanon check` = 0 stale (или задокументированное исключение)

---

Упавший пункт → итерация `iterations/it-NNN/` (source: e2e) с сырым логом.
