# it-007: любая покупка при живой подписке → queued (апгрейд без мгновенного действия и переноса дней)

## Что нашли

Код отработал ровно по спроектированному сценарию 3.3 (гейт Д1–Д3):
смена тира вверх = апгрейд → старая `replaced`, новая `active` сразу,
остаток дней переносится. Кейс оператора вскрыл слепое место дизайна:
юзер мог хотеть «купить Pro на год вперёд, пока действует Basic» —
легитимное намерение, которое сценарий 3.3 не различал и реализовать
не позволял.

## Что решили

Решение оператора (2026-10-10, словами в чате), в формулировке
принятия гейта: **любая покупка при живой подписке → в очередь со
стартом = конец текущей, ровно оплаченный период, без переносов**.
Апгрейд перестаёт быть особым случаем, статус `replaced` и
`carried_days` уходят, правило ≤1 queued уже обеспечивает «одна
будущая подписка». Цена: купивший апгрейд ждёт окончания текущей —
осознанный выбор, юзер видит даты до оплаты.

Апгрейд перестаёт быть особым случаем: ветки 3.2/3.3/3.4 сливаются в
один queued-путь, сравнение display_order удаляется.

## Что поправили

- `src/services/subscription_service.py`:
  - `_purchase_impl`: ветки 3.2 (продление) / 3.3 (апгрейд:
    replace+carry) / 3.4 (даунгрейд) слиты — любой тир при живой
    active → INSERT queued, `started_at = active.expires_at`,
    `expires_at = started_at + оплаченный период`;
  - удалены `remaining_days()` и поле `carried_days` у
    `PurchasePreview`; `preview_purchase` возвращает `renewal`
    для любой покупки при живой active;
  - `replace_subscription` (REPLACED) потоком больше не вызывается.
- `src/bot/payment_callbacks.py`:
  - `render_purchase_confirmation` — один текст для любой покупки при
    активной подписке (даты старта/окончания, имя текущего тира);
    ветки «Апгрейд действует сразу» и «carried N дн.» удалены;
  - `_maybe_confirm_subscription_purchase` — имя текущего тира
    подгружается всегда, без ветки по сценарию.
- Enum `REPLACED` и репо-метод `replace_subscription` остаются в
  схеме (историю не ломаем), но поток их больше не создаёт.
- Тесты: `test_subscription_purchase_140.py` (TestScenario33 →
  queued-семантика, без replace/carry), `test_payment_confirm_ux_140.py`
  (превью renewal для любого тира; текст без «действует сразу»).
- Доки: `docs/dev/data/subscription-statuses.md` (replaced = legacy),
  `WHATSNEW.md`.

Прогон: 1117 unit-тестов зелёные; ruff/black/mypy чисто по
затронутым файлам.
