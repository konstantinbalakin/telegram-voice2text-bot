# it-008: предупреждение о замене queued в подтверждении покупки

## Что нашли

Правило ≤1 queued (it-007): любая покупка при живой active отменяет
существующую queued и ставит новую. Отмена происходит молча — юзер,
запланировавший Pro, может купить Basic и потерять запланированный тир,
не зная об этом. `preview_purchase` о существующей queued не сообщал,
`render_purchase_confirmation` предупреждение не рисовало.

Требование оператора: предупреждать о замене, но без тавтологии
(«подписка заменяет подписку»).

## Что решили

Предупреждение называет, ЧТО именно отменит покупка, — запланированный
тир по имени, а не абстрактную «подписку»:

- `PurchasePreview` получает флаг `replaces_queued`;
- `preview_purchase` ставит его, если у юзера есть queued;
- текст подтверждения при флаге: «⚠️ Запланированная подписка
  <Тир> будет отменена — в очередь встанет новая.» (понижается до
  варианта без имени, если тир не нашёлся);
- хендлер подтягивает имя queued-тира из БД только при флаге.

## Что поправили

- `src/services/subscription_service.py`:
  - `PurchasePreview.replaces_queued: bool = False`;
  - `preview_purchase`: `get_queued_subscription` → `replaces_queued`.
- `src/bot/payment_callbacks.py`:
  - `render_purchase_confirmation(..., replaces_queued_tier_name="")` —
    предупреждение при `preview.replaces_queued`, имя тира подставляется,
    тавтология исключена (назван конкретный отменяемый тир);
  - `_maybe_confirm_subscription_purchase` — при флаге читает
    queued и её тир в той же сессии.
- Тесты (`tests/unit/test_payment_confirm_ux_140.py`):
  - preview: без queued → False; с queued → True; отменённая queued →
    False;
  - рендер: предупреждение с именем тира; без тавтологии («заменяет»
    нет в тексте); деградация без имени; без queued предупреждения нет;
  - хендлер: queued в БД → в тексте «Запланированная подписка Pro будет
    отменена», платёж не создан.

Прогон: 1123 unit-теста зелёные (было 1117, +6); ruff/black/mypy чисто
по затронутым файлам.
